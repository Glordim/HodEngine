# Editor: Version control, before calling it v1

- Close / Hot Reload during a long operation (Pull, Push: up to 30 min with LFS) blocks invisibly: OnProjectClosed waits for the whole queue
	- On close, only run the ReleaseEdit, drop the rest, and show what is waited for
- With LFS lockable files, a save during a Pull/Push (or the first fetch after opening, up to 60s) freezes the editor: PrepareWrite waits behind it
	- Refuse the save with a clear message when the worker is busy with a long operation (or wait a few seconds at most)
- SSH remotes can hang 2 to 30 min: ssh asks for a passphrase / host key confirmation in the hidden console (CREATE_NO_WINDOW)
	- -o BatchMode=yes, without overriding a core.sshCommand set by the user
- A timeout kills git only (TerminateProcess): git-remote-https / git-lfs / ssh stay alive, a .git/index.lock may stay and make every command fail
	- Kill the whole tree (Job Object in Process.windows), recognize the index.lock error and explain it
- Non ASCII names: FileSystem uses the ANSI functions (GetFileAttributesA, CreateFileA; code page 1252 here)
	- GitProvider::Add skips them silently, GetFilesToCheckout never checks them out, Submit classifies them as deleted (still committed right thanks to git commit --only)
	- Locally: ask git (status) what exists rather than FileSystem. For real: FileSystem on the W functions (whole engine)

# Modules: manifests declaring what a module brings (as _versionControlSystems for the new project form)

So that what needs a module not loaded (disabled, or not loaded yet) can name it
- Components: a MissingComponent suggests the disabled module that has its type ("RigidBody2d: module Physics disabled, enable it?")
- Asset types: an asset of an unknown type suggests its module
	- The asset header must hold the type's name, not only its hash, to find it in the manifests
- Project templates, offered in NewProjectForm (a template can check the modules it needs)
- Long lists (components) not written by hand: generate that part of Modules/<Name>.json at build time (what the module registers, or the reflection)
- _versionControlSystems: nothing checks the names match the providers' GetName() (a TestsEditor test loading VersionControlEditor)

# Editor: Add Component popup, tolerant search (step 2 of its overhaul)

- The search is a plain substring match: a piece of a word, a wrong case or a typo finds nothing useful
	- A scored matcher in Editor (SearchMatcher), case and space insensitive: prefix > word start > substring > subsequence > initials ("bc2" -> Box Collider 2D)
	- Results sorted by score, the matched letters highlighted, with tests
- Then the same search and categories in the UI editor's Add Node menus

# Reflection: editor-only data out of the non-editor builds

Display name, description, category and icon only serve the editor, but stay declared next to the class (game modules have no editor library)
- HOD_EDITOR_DATA define (PUBLIC on Core, on when the editor is built) + HOD_EDITOR_TRAIT(target, Trait, ...) macro, compiled out otherwise
- GetDisplayName editor only: its runtime users take the type name (UI NodeFactory naming new nodes, ComponentFactory and NodeRef logs, ImGui Window title)
- Icons: for now components and UI nodes include HodEngine/ImGui/Font/IconsMaterialDesignIcons.h directly (no separate MDI lib in the retail CMake)
	- Wrap that include in #if HOD_EDITOR_DATA
- ReflectionTraitHide on properties is not editor only (UI PropertyOverride IsOverridable uses it at runtime): only the type-level Hide (not offered in Add Component) is

# Physics: colliders without a Rigidbody2d (Unity's way)

For now a collider without a Rigidbody2d on its entity or its parents logs an error and creates no shape
- Lookup unchanged: GetComponentInParent<Rigidbody2dComponent> first (a child's collider stays a fixture of its parent's body, GetParentOffset already handles it)
- Only when none is found: an implicit static body, one per entity holding such colliders (not a single global body: it can follow its node with SetTransform)
	- Follows its node only when the node changes, not every step
- Rigidbody2d added / removed at runtime: its colliders (and its children's) move between it and the implicit body
	- Also fixes the shape left on a removed rigidbody's body
- Collision / trigger events on the collider (its entity), not only on the Rigidbody2d: a static trigger zone (checkpoint, death zone) then needs no rigidbody
	- In the callbacks, the other side is the rigidbody or, without one, the collider
- Then a static Rigidbody2d only serves to group colliders (one body for a whole level's tiles, one place for the group's events)
	- Its other options (GravityScale, FixedRotation, ContinuousCollision, FreezePosition) do nothing in Static: hide them in the inspector in that mode?
- Rigidbody2dComponent::OnFixedUpdate teleports a static body to its node every step (TeleportToNode), even if it never moves
